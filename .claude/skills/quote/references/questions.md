# 질문 목록 (메인 대화가 AskUserQuestion으로)

한 번에 최대 4문항. 선택지가 있는 건 선택지로, 나머지는 "기타(직접 입력)"로 받는다. 이미 받은 값은 건너뛴다. 끝내 모르는 값은 비우고 "확인 필요".

## 1. 처음 시작 (data/company.md가 비어 있을 때만)

| 질문 | 선택지 |
|---|---|
| 처음이시네요. 어떻게 시작할까요? | 예시 회사로 체험(웹 제작 회사, 가상) / 우리 회사로 시작 |
| (우리 회사) 회사 정보를 어떻게 받을까요? | 회사 자료 파일 주기(사업자등록증 · 회사소개서 · 가격표) / 직접 입력 |
| (파일) 파일을 `data/회사자료/`에 넣거나 채팅창에 끌어다 놓아 주세요 | 넣었어요 / 직접 입력으로 바꾸기 |
| (읽은 뒤) 이렇게 읽었어요. 맞나요? (상호 · 대표 · 사업자번호 · 업태 · 주소 요약) | 맞아요, 저장 / 고칠 곳 있음(직접 입력) |
| 우리 회사 견적서 양식이 있나요? | 없음(기본 양식) / 있음(`templates/custom/`에 hwpx 넣기) |
| 업종 | 제조 / 유통·도소매 / 서비스 / 교육 / IT·웹 / 기타(직접) |
| 상호 · 대표 · 사업자번호 · 연락처 · 주소 | 직접 입력. 사업자번호를 모르면 비워 둔다 |
| 설립일 · 연혁·실적(선택, 과업지시서 1장에 씀) | 건너뛰기 / 직접 입력 (예: 2024년 설립, 2025년 ○○ 납품) |
| 계약 조건(선택) | 없음 / 직접 입력 (예: 수정 2회, 하자보수 3개월) |

단가표(data/prices.md)가 비어 있으면: "주로 파는 품목·서비스 2~3개의 이름 · 단위 · 단가(부가세 별도)를 알려 주세요".
업종별 예시는 보여 주기만 한다(제조: 부품 가공·개 / 유통: 상품 납품·박스 / 서비스: 컨설팅·회 / 교육: 강의·시간 / IT·웹: 페이지 제작·페이지). 단가는 지어내지 않는다.

## 2. 견적 정보

| 질문 | 선택지 |
|---|---|
| 고객사 이름 | 직접 입력 |
| 담당자 이름과 직함 | 직접 입력 (예: 이수진 과장) |
| 건명 | 직접 입력 (예: 사무용 가구 납품, 직원 교육 3회) |
| 품목 (여러 개) | data/prices.md 품목 이름들 (4개가 넘으면 나눠 묻기) / 새 품목(직접 입력) |
| 품목별 수량 | 단가표 단위 그대로 (개 · 시간 · 페이지 · 식 …) |
| 견적일 | 오늘 / 직접 입력 |
| 납기 (납품·완료 예정일) | 직접 입력 / 미정 |
| 결제 조건 (선택) | 없음 / 계약금 50%·잔금 50% / 납품 후 일시불 / 직접 입력 |
| 비고 | 없음 / 직접 입력 |

새 품목: "○○의 단위와 단가를 알려 주세요" → "단가표에 추가할까요? (예 / 이번만 쓰기)".

## 3. 요청 기록 형식 `outputs/_requests/{고객코드}.json`

```json
{
  "code": "badasangsa",
  "customer": "바다상사",
  "contact": "이수진 과장",
  "service": "건명",
  "date": "2026. 10. 30.",
  "open": "2026. 11. 30.",
  "payment": "",
  "items": [
    {"name": "단가표 품목 이름", "unit": "개", "qty": 10, "price": 50000}
  ],
  "note": ""
}
```
`service` = 건명, `open` = 납기, `template` = 우리 회사 양식 경로(없으면 생략). 품목 이름·단위·단가는 단가표 글자 그대로. 이 기록이 검산(check.js)의 기준이다.
