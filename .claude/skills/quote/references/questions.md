# 질문 목록 (메인 대화가 AskUserQuestion으로)

한 번에 최대 4문항. 선택지가 있는 건 선택지로, 나머지는 "기타(직접 입력)"로 받는다. 이미 받은 값은 건너뛴다.

## 1. 회사 정보 (data/company.md가 비어 있을 때만)

| 질문 | 선택지 |
|---|---|
| 어떤 회사로 견적서를 만들까요? | 예시 회사(새벽웹스튜디오)로 먼저 해 보기 / 우리 회사 정보 입력하기 |
| (입력을 고르면) 상호 · 대표 · 사업자등록번호 · 업태 · 주소 · 연락처 | 직접 입력. 모르는 칸은 비워 둔다 |
| 계약 조건(수정 횟수 · 하자보수 기간) | 수정 2회 · 하자보수 3개월 / 수정 3회 · 하자보수 6개월 / 직접 입력 |

단가표(data/prices.md)가 비어 있으면: 「예시 단가표 쓰기 / 품목마다 단가 입력」.

## 2. 견적 정보

| 질문 | 선택지 |
|---|---|
| 고객사 이름 | 직접 입력 |
| 담당자 이름과 직함 | 직접 입력 (예: 이수진 과장) |
| 용역명 | 홈페이지 신규 제작 / 홈페이지 리뉴얼 / 쇼핑몰 제작 / 직접 입력 |
| 품목 (여러 개 고르기) | data/prices.md의 품목 이름들 (4개가 넘으면 두 번에 나눠 묻는다) / 직접 입력 |
| 품목별 수량 | 페이지 단위 품목만 묻는다. 식 단위는 1 |
| 견적일 | 오늘 / 직접 입력 |
| 오픈 희망일 | 직접 입력 (모르면 "미정") |
| 비고 | 없음 / 직접 입력 (제외 항목 · 확인 필요 사항) |

단가표에 없는 품목: "○○의 단가와 단위를 알려 주세요" → "단가표에 추가할까요? (예 / 이번만 쓰기)".

## 3. 요청 기록 형식 `outputs/_requests/{고객코드}.json`

```json
{
  "code": "badasangsa",
  "customer": "바다상사",
  "contact": "이수진 과장",
  "service": "홈페이지 리뉴얼",
  "date": "2026. 10. 30.",
  "open": "2026. 11. 30.",
  "items": [
    {"name": "기획·화면설계", "unit": "식", "qty": 1, "price": 800000},
    {"name": "서브 페이지 디자인·제작", "unit": "페이지", "qty": 7, "price": 250000}
  ],
  "note": "부가세 별도. 도메인·호스팅은 기존 것 사용"
}
```
품목 이름·단위·단가는 단가표 글자 그대로. 이 기록이 검산(check.js)의 기준이다.
