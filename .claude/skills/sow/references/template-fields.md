# 과업지시서 원고 쓰는 법

`node scripts/hwpx.js draft sow {고객코드}`가 만든 틀(templates/sow-outline.md)의 ( ) 자리를 모두 채운다. 제목 줄(`**1. …**` · `**과업 1. …**` · `**1) 과업 개요**`)과 목차 줄, `(과업명)` 같은 목록 라벨은 그대로 둔다. 제목은 굵은 글자만 쓰고 □ · 색 띠는 넣지 않는다. 구조·분량·문장은 [writing-guide.md](writing-guide.md), 품목 묶기는 [task-mapping.md](task-mapping.md).

| 부분 | 무엇을 | 어디서 |
|---|---|---|
| 표지 | 「용역 과업지시서」 아래 과업명 · 작은 표(작성일 · 기업명 · 대표자명) · 서명 (인) | 견적서 건명·고객사, `data/company.md` 상호·대표. 발주처 대표자 이름을 모르면 "확인 필요" |
| 1. 위탁회사 현황 및 실적 | 기업체명 · 대표자 · 설립일자 · 사업자등록번호 · 소재지 · 연락처 · 업종(주제품) · 연혁 및 실적 | `data/company.md`. 없는 칸은 "확인 필요" |
| 2.1 과업 개요 | 2~3문장 + (과업명)(발주처)(수행기관)(과업 기간)(과업 금액) | 견적서, 요청 기록 `sow.reason`·`sow.start`·`open`. 과업 금액은 견적서 합계금액 줄 그대로 |
| 2.2 과업별 내용 | `### 과업 N. 이름` 블록을 과업 수만큼: 1) 과업 개요 · 2) 과업 목적 (가)(나)(다) · 3) 과업 범위 표(항목 | 내용) · 4) 산출물 예시 표 | 견적 품목, 요청 기록 `sow.must` |
| 3. 과업 추진일정 | 과업마다 한 줄 + `통합 점검, 최종 산출물 납품 및 검수`. 열은 착수일부터 납기까지 주차, 하는 주에 ■ | 요청 기록 |
| 4. 최종 산출물 | 번호 · 산출물 · 수량 · 형태 · 비고(관련 과업) | 2.2의 주 작업물 |
| 5. 검수 계획 | 1) 검수항목 표 3행 이상(□ 적정 / □ 부적정) · 2) 검수(테스트) 방안 (1)(2)… · 하자보수 · 보안 · 저작권 · 자료 제공 | `data/company.md` 계약 조건. 없으면 "확인 필요" |

## 산출물 예시 표
- 제목 줄 · 그림 칸 2개 · 개요 · 주 작업물 순서. 그림 칸에는 `(납품 전 실제 화면으로 교체)`를 그대로 둔다. AI로 그린 그림은 넣지 않는다.
- `data/참고이미지/`에 사용자가 넣은 실제 화면이 있을 때만 그 파일을 쓴다. 인터넷 이미지는 내려받지 않는다.
