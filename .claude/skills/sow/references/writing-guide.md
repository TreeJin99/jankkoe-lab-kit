# 과업지시서 쓰는 법 (구조 · 분량 · 문장)

실제로 쓰인 과업지시서(위탁 용역)를 재어 본 기준입니다. 예시는 모두 가상입니다.

## 구조 (번호 그대로)
표지(과업명 · 작성일 · 발주처 · 대표자명 · 서명 (인)) → 목차 →
1. 위탁회사(계약당사자) 현황 및 실적 → 2. 과업 내용(2.1 과업 개요 · 2.2 과업별 내용) → 3. 과업 추진일정 → 4. 최종 산출물 → 5. 검수 계획.
큰 목차(1.~5.)는 늘 새 쪽 맨 위에서 시작합니다(견본 서식이 알아서 나눔).

## 분량 (검산이 모자라면 돌려보냄)
| 부분 | 기준 |
|---|---|
| 2.1 과업 개요 | 배경·무엇을 만드는지 2~3문장 + (과업명)(발주처)(수행기관)(과업 기간)(과업 금액) 목록 |
| 과업 수 | 2~5개 (견적 품목을 묶어서) |
| 1) 과업 개요 | 2문장 이상 |
| 2) 과업 목적 | (가)(나)(다) 3개, 각 40~80자 |
| 3) 과업 범위(내용) | 표 3~6행, 내용 칸 30~80자 (화면·기능·조건·횟수까지) |
| 4) 산출물 예시 | 개요 + 주 작업물(산출물(형태) 2~3개) + 예시 그림 1장 |
| 5. 검수 계획 | 검수항목 3~5개(□ 적정 / □ 부적정) + 검수(테스트) 방안 (1)(2)… |
| 문서 전체 | 6~9쪽 |

## 문장
- 개요는 "~함."으로 끝나는 2~3문장. 첫 문장은 왜(지금 문제), 둘째 문장은 무엇을 어떻게.
- 목적은 `(가) 짧은 라벨 : 무엇을 · 왜 · 어떻게` 한두 줄. 예) `(가) 직접 운영 : 관리자 로그인 후 공지를 등록·수정·삭제할 수 있게 해, 외부에 수정을 요청하는 시간을 줄임`
- 범위 내용은 명사 나열이 아니라 "무엇을 어디까지 어떤 조건으로". 예) `이름·연락처·내용 입력, 필수 항목 확인 후 담당자 메일로 전달`
- 셋 목적은 서로 겹치지 않게(사용자 · 운영 · 확장, 또는 품질 · 일정 · 비용).

## 지어내지 않기
- 고객 고유 사실(방문자 수, 매출, 대표자 이름, 설립일 등)은 받은 값만. 모르면 "확인 필요".
- 업종 일반 수준의 범위·요구(예: 휴대폰 화면 대응, 개인정보 동의, 납품 전 점검)는 써도 된다.
- 과업지시서는 할 일을 정하는 문서다. 결과로만 알 수 있는 것(완성 화면, 실제 주소, 성과 수치)은 쓰지 않는다. 주소는 "(납품 시 기재)".

## 업종별 예시 (가상)
| 업종 | 과업 예 | 범위 내용 예 | 주 작업물 예 |
|---|---|---|---|
| 웹 | 기획 · 디자인 · 기능 개발 | 메인 시안 승인 후 서브 같은 기준 적용(수정 2회) | 화면설계서(PDF), 완성 화면(서버 설치) |
| 제조 | 설계 · 시제품 · 양산 | 도면 승인 후 시제품 2개 가공, 치수 공차 ±0.1mm 검사 | 도면(DWG), 시제품(실물), 검사 성적서(PDF) |
| 교육 | 과정 설계 · 강의 운영 · 평가 | 회차별 교안과 실습 자료 준비, 출석·만족도 기록 | 교안(PDF), 출석부, 결과 보고(PDF) |
| 유통 | 상품 준비 · 납품 · 사후 관리 | 납품 일정에 맞춰 포장 기준대로 출고, 불량은 교환 | 납품 목록, 거래명세서 |
